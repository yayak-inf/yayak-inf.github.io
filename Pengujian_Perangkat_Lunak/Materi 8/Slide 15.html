Contoh Kasus

Studi Kasus: Website Login Sederhana

Fokus pada endpoint login untuk mengevaluasi stabilitas dan kinerja saat diakses banyak pengguna secara bersamaan.

Objek Pengujian

Menguji performa pada halaman/form login dan/atau API login (HTTP/HTTPS) yang memvalidasi kredensial pengguna.

Endpoint

POST /login (contoh), request body + response.

Dependensi

DB user, hashing password, session/token.

Kualitas Kritis

Tahan terhadap lonjakan, minim error/timeout.

Metrik

Response time, throughput, error rate.

Tujuan Pengujian

Apa yang ingin dibuktikan dari sisi performa?

stability first

Konsistensi latensi

Menilai apakah response time stabil saat beban naik.

Kapasitas layanan

Melihat throughput saat banyak user login bersamaan.

Error & timeout

Mengukur error rate saat beban tinggi (5xx/timeout).

Indikasi bottleneck

Menentukan titik lemah: aplikasi, DB, atau jaringan.

Alur Login (Konseptual)

Request melewati beberapa komponen

flow

User → Web/App → Auth → Database → Response

E2E

User

App

Auth

DB

Latensi

Dipengaruhi hashing, query user, dan I/O.

Error

Bisa muncul dari DB pool, timeout, rate limit.

Hasil yang Diharapkan

Kriteria sukses uji performa login

Outcome

Waktu respon konsisten

Tidak terjadi lonjakan besar pada P95/P99 saat user meningkat.

Error minimal

Error rate rendah; tidak dominan 5xx/timeout saat beban target.

Server tidak kehabisan resource

Tidak terjadi crash; aplikasi tetap melayani request secara stabil.

Catatan

Angka target spesifik dibahas pada slide metrik; yang utama adalah tren stabil saat beban meningkat.

Studi kasus ini akan dipakai sebagai dasar skenario uji 50/100/200 user pada JMeter.

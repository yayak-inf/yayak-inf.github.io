Interpretasi Hasil

Analisis Hasil Testing

Fokus analisis: waktu respon, throughput, error rate, dan resource server. Hasil yang baik bukan hanya cepat, tetapi stabil saat beban meningkat.

Parameter yang Dipantau

Empat indikator utama untuk menyimpulkan performa

checklist

Waktu Respon

Lihat P95/P99 dan tren kenaikan saat user bertambah.

Interpretasi cepat

naik tajam = indikasi bottleneck

Throughput

Ukur request/detik atau transaksi/detik. Idealnya naik seiring beban.

Interpretasi cepat

stagnan = kapasitas mulai mentok

Error Rate

Catat 4xx/5xx/timeout/429 dan pola meningkatnya pada level beban lebih tinggi.

Interpretasi cepat

5xx/timeout = server overload

Resource Server

CPU, memori, koneksi DB, thread pool, dan I/O (disk/jaringan) saat test berjalan.

Interpretasi cepat

resource tinggi + latensi naik

Jika Terjadi Masalah → Tindakan

Rekomendasi awal sebelum investigasi mendalam

Quick Actions

Respon lambat

Optimasi query, caching, indexing, kurangi payload, cek dependency (DB/3rd party).

Banyak error

Periksa log 5xx/timeout, konfigurasi pool (DB/HTTP), rate limit, dan validasi data uji.

Resource tinggi

Profiling CPU, cek memory leak, atur concurrency/thread pool, scaling vertikal/horizontal.

Prinsip: bandingkan antar level

Kenaikan user seharusnya meningkatkan throughput sampai titik tertentu. Jika latensi/error meningkat lebih cepat daripada throughput, sistem mendekati batas kapasitas.

Contoh Tren (Ilustratif)

Bandingkan 50/100/200 user (P95 & error)

trend

P95 (ms)

Naik wajar saat beban meningkat, tetapi hindari lonjakan tajam.

Error (%)

Error meningkat pada level tinggi menandakan kapasitas terlampaui.

Aturan Interpretasi (Ringkas)

Membantu menyimpulkan hasil dengan cepat

Rule of thumb

Kondisi baik

stable

Throughput naik, P95 naik perlahan, error rendah → sistem masih dalam kapasitas target.

Perlu investigasi

warning

P95 naik cepat tapi error belum tinggi → kemungkinan bottleneck (DB/cache/network) mulai muncul.

Tidak stabil

overload

Error meningkat, timeout/5xx dominan, throughput stagnan/turun → kapasitas terlampaui (butuh optimasi/scaling).

Catatan praktikum

Gunakan hasil ini untuk menulis analisis singkat: jelaskan tren, temuan (bottleneck/indikasi), dan rekomendasi perbaikan.

Setelah analisis, rangkum hasil per level (50/100/200) dan simpulkan apakah target performa tercapai.

Metrik Performance

Metrik Performance yang Dipantau

Metrik digunakan untuk menilai apakah sistem memenuhi target kecepatan, kapasitas, dan stabilitas saat beban meningkat.

Response Time

Latensi end-to-end (user → server → user)

ms / s

Rata-rata

Gambaran umum, tapi bisa menutupi outlier.

P95/P99

Fokus pada “pengalaman terburuk” pengguna.

End-to-end

Termasuk network, app, dan DB.

Interpretasi cepat

lebih rendah = lebih baik

Jika P95 meningkat tajam saat user bertambah, indikasi bottleneck (DB, cache miss, thread pool).

Throughput

Jumlah request/transaksi per satuan waktu

RPS / TPS

Kapasitas

Seberapa banyak sistem memproses request.

Skalabilitas

Harus naik saat user dinaikkan (hingga batas).

Bottleneck

Stagnan meski beban naik → ada limit.

Interpretasi cepat

lebih tinggi = lebih baik*

*Selama response time dan error tetap dalam batas target. Throughput tinggi dengan error tinggi bukan performa yang baik.

Error Rate

Persentase request gagal (5xx/timeout/429)

%

5xx

Bug aplikasi, DB down, resource habis.

Timeout

Antrian panjang, koneksi lambat, deadlock.

429/Limit

Proteksi aktif (rate limit/backpressure).

Interpretasi cepat

lebih rendah = lebih baik

Naiknya error saat beban meningkat biasanya menandakan batas kapasitas atau konfigurasi pool/limit yang tidak memadai.

Concurrent Users

Jumlah user aktif yang berjalan bersamaan

VU

Beban

Merepresentasikan trafik di waktu yang sama.

Ramp-up

Naik bertahap untuk mencari titik kapasitas.

Distribusi

Atur skenario: login, browse, transaksi, dsb.

Interpretasi cepat

lebih tinggi = lebih berat

Jika VU naik, tetapi throughput tidak bertambah dan latency/error meningkat, kapasitas sudah terlampaui.

Gunakan metrik ini bersama-sama: tidak cukup melihat satu metrik saja (mis. throughput tanpa error/latensi).

Bug Report

Struktur Bug Report

Komponen Wajib

Sebuah bug report yang efektif harus memuat informasi lengkap agar developer dapat memahami, mereproduksi, dan memperbaiki masalah dengan cepat.

Quality Assurance

ID Bug

Identitas unik bug (misal: BUG-001) untuk pelacakan referensi.

Judul Bug

Ringkasan singkat dan jelas tentang masalah yang terjadi.

Deskripsi

Penjelasan detail tentang bug, konteks, dan kondisi saat kejadian.

Langkah Reproduksi

Urutan langkah demi langkah untuk memunculkan bug kembali.

Expected Result

Hasil yang seharusnya terjadi jika sistem berjalan normal.

Actual Result

Hasil nyata yang terjadi (error/penyimpangan) saat pengujian.

Screenshot / Lampiran

Bukti visual berupa gambar error, log file, atau rekaman video untuk memperjelas laporan.
